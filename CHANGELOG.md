# Changelog

All notable changes to this project are documented here.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the
project uses [Semantic Versioning](https://semver.org/) (see
[docs/versioning.md](docs/versioning.md)).

## [Unreleased]

## [0.21.0] - 2026-10-12

### Added
- ADSB_Test: Wireless-Tag WT01P4C5-S1 (ESP32-P4 + ESP32-C5) symbol and hand-solder footprint (`gen_wt01p4c5.py`, from datasheet v1.3; land pattern to be checked on a real module).
- ADSB_Test: generated MCU Module sheet (page 6: module, 5 V decoupling, 32.768 kHz crystal, I2C pull-ups, BOOT/RESET buttons, C5 strap pull-up, DNP C5 JTAG, spare-pin test pads) and RTC sheet (page 7: DS3231M on VBACKUP) via `gen_mcu.py`.
- ADSB_Test BSP: DS3231M driver (`bsp_rtc_init/get_time/set_time/get_temperature`) and test `[rtc_ext]` (skips if no DS3231M is found).
- ADSB_Test test plan: 1.15 (WTDKP4C5-S1 dev board: chip revision, esp_hosted, pad check) and 1.16 (DS3231M breakout).
- DS3231M datasheet entry.

### Changed
- ADSB_Test adopts the WT01P4C5-S1 module (Q26) and a DS3231M RTC (Q27). Pins: PM_ALERT GPIO5 → 20, C5 reset 54 → 13 and C5 wake 6 → 12 (inside the module), RTC_INT on GPIO6; spares now 36 and 54.
- ADSB_Test power: RS404 now feeds 5V_MCU (module, PM2 CH2); RS405 now 3V3_SD (PM2 CH3); 3V3_P4/3V3_C5 removed. VBACKUP feeds the DS3231M instead of the P4 VDD_BAT.
- ADSB_Test sheets renamed: ESP32-P4 → MCU Module (`mcu_module.kicad_sch`), ESP32-C5 → RTC (`rtc.kicad_sch`).
- ADSB_Test test app: 16 MB flash; builds for P4 silicon below v3 by default (`sdkconfig.rev3` overlay for v3; replaces `sdkconfig.rev1`).
- Requirements CORE-01/02, architecture, open questions, READMEs and PCB-manufacturing rules updated for the module.

## [0.20.0] - 2026-10-12

### Added
- ADSB_Test: optional RF can SH1401 (Laird BMI-S-203-F frame + BMI-S-203-C lid, DNP) over the m1421, combiner and ESD; GNSS can planned with the GPS sheet.
- ADSB_Test: P4 + C5 module option (Wireless-Tag WT01P4C5-S1, fallback Waveshare ESP32-P4-Module) compared in architecture.md, with the pin moves it needs; open questions Q26 (adopt the module) and Q27 (external RTC, as the module has no P4 VBAT pin).
- Datasheet entries for WT01P4C5-S1, Waveshare ESP32-P4-Module and the Laird shield.

### Changed
- pcb-manufacturing.md: castellated-module and RF-can footprint rules.

## [0.19.0] - 2026-10-12

### Added
- `tools/kicad_fp_handsolder.py` + `hardware/gen/gen_footprints.py`: hand-solder footprint copies
  (edge pads lengthened, plated holes in bottom/exposed pads). Made for the ADSBee m1421 (+1.5 mm,
  holes in the MP ground pads), STUSB4500 QFN-24, PAC1954 VQFN-16 and TPS62933 SOT-583.
- Hand-saved datasheets registered (STUSB4500, USBLC6-2, PAC195x, CP2102N, BQ25792); the fetch script
  now uses a hand-saved copy for `manual` entries without retrying the blocked site.

### Changed
- **Rev 1 is fully hand-assembled; PCBWay makes the PCB only** (Q24). docs/pcb-manufacturing.md has
  the footprint rules and the parts needing hot air / a hot plate.
- Generated sheets use the hand-solder footprints; logic gates SC-70 → SOT-23; PD power-path FET
  DMP3013SFV (PowerDI) → **FDS9435A (SO-8)**.
- PAC1954 addresses fixed from the datasheet: 0x10 / 0x11 / 0x12 (ADDRSEL 0 Ω / 499 Ω / 806 Ω);
  STUSB4500 VSYS / VBUS_VS_DISCH / DISCH wiring confirmed from DS12499.

## [0.18.0] - 2026-10-12

### Added
- ADSB_Test **POWER slide switch** (SW401, through-hole, case edge): OFF disables both bucks via a
  shared `PWR_EN`; the charger keeps charging from USB while off.
- **Always-on VBACKUP** (3.0 V, MCP1703 ~2 µA from VSYS) for the P4 VDD_BAT (RTC) and GPS V_BCKP, with
  an optional diode-OR'd CR1220 holder (not fitted).
- `docs/pcb-manufacturing.md`: PCBWay capabilities, start design rules, hand-solder policy and the
  list of fine-pitch parts for PCBWay assembly. Open questions Q23 (answered), Q24 (assembly), Q25.

### Changed
- All generated passives and LEDs moved to **0805 HandSolder** footprints (1206 HandSolder for bulk
  caps and shunts), test points to 1.5 mm pads. Only the ESD7351 (SOD-523 only) stays small.
- The two buck converters share one enable/UVLO divider.

## [0.17.0] - 2026-10-12

### Added
- ADSB_Test **power schematics** generated by `hardware/gen/gen_power.py`:
  - Power Input: User USB-C, STUSB4500 PD sink + DMP3013SFV power path, SMAJ20A TVS, USBLC6-2 ESD,
    input shunt, Dev-VBUS solder jumper (default open).
  - Charger Battery: BQ25798 2S/750 kHz with datasheet values (PROG 8.2k, 2.2 µH, caps, TS divider,
    single-input VAC/ACDRV wiring), 2S pack connector with NTC, battery and VSYS shunts.
  - Power Rails: 2 × TPS62933 (5 V, 3.3 V), Kelvin shunt per rail, TPS22917 load switches for
    5V_LCD / 3V3_ETH / 3V3_GPS / 3V3_M1421, test points.
  - Power Monitor: 3 × PAC1954 on the 12 sense pairs, PM_ALERT.
- Generator: footprint defaults from the library symbol, missing-footprint check, text placement
  for right-pinned symbols, power flags honour local nets.
- Datasheets: TPS2596, TPS22917, DMP3013SFV, USBLC6-2 added to the reference library.

### Changed
- USB-A eFuse TPS25200 → **TPS2596** (KiCad symbol available); 5 V buck fixed as TPS62933.
- M1421 sheet: temporary power flags removed (rails now driven by the power sheets).

### Notes
- ERC on the whole project: 16 items, all cross-sheet drivers on sheets not yet generated. Items to
  confirm against vendor datasheets are listed in architecture.md "Power sheets: schematic status".

## [0.16.0] - 2026-10-12

### Added
- Reference board: `bsp_battery_voltage_mv()` (main battery on GPIO20, ADC curve-fitting
  calibration, ×3 divider) and tests `[battery]` (2 s min/avg/max, flags "no battery" when the
  charger output is cycling) and `[rtc_battery]` (RTC memory + clock retention across a full
  power-off on the VDD_BAT coin cell). `CONFIG_ESP_VBAT_INIT_AUTO=y`.
- README: the two batteries explained (main Li-ion vs RTC coin cell), with a caution that D1
  trickle-charges the coin-cell node (suits ML1220, not CR1220). ADSB_Test open question Q23.

### Fixed
- Schematic generator: Reference/Value text now placed outside the symbol body (no overlap with pin
  names); M1421 sheet re-spaced so no labels overlap or leave the frame; stale "74LVC1G157" in the
  sheet notes corrected.

### Verified on hardware
- Full suite 16 tests, 0 failures. BAT 4.17 V steady in one run, 0.65 V in another (likely no battery
  fitted). VBAT state NORMAL; retention marker set (power-off check pending).

## [0.15.0] - 2026-10-12

### Added
- `tools/kicad_sch_gen.py`: generator that builds KiCad sheets from Python (copies library
  symbols, places them, connects pins via wire stubs + net labels / power symbols / no-connects).
- ADSB_Test **M1421 sheet schematic** (generated by `hardware/gen/gen_m1421.py`): m1421 module,
  **ADSBee 1421 Dev Kit header J1402** (1x6 2.54 mm, Dev Kit comms pinout), 10-pin J-Link header,
  74LVC1G97 RX mux, 74LVC1G32 SYNC OR, 74LVC1G07 Dev reset buffer, activity LEDs, SCN-2-11+ combiner
  + ESD + edge SMA, decoupling, test pads for the LR2021 lines. Netlist checked; ERC shows only the
  expected cross-sheet items (P4/Dev drivers not drawn yet).
- Architecture: Rev A fit options (Dev Kit header by default, solder the module later), pogo-pin
  assessment. Open question Q22 recorded. 74LVC1G97 datasheet added to the reference library.

### Changed
- m1421 RX mux part: 74LVC1G157 → **74LVC1G97** in 2:1-mux configuration (no KiCad symbol for 1G157).

## [0.14.0] - 2026-10-12

### Added
- microSD tests: 4 MiB patterned write + read-back verify with speed and free space, and a
  persistence counter for a power-cycle check (both in `[sdcard]`).

### Fixed
- `[wifi]` crashed when run a second time in the same boot (duplicate default STA netif assert);
  the Wi-Fi stack is now initialised once.
- `[usb]` failed when run a second time (`usb_host_install` → ESP_ERR_INVALID_STATE): the library
  daemon now keeps handling events until all devices are freed, then uninstalls (Espressif pattern).

### Verified on hardware (reference board, rev v1.3)
- Full suite run twice in one boot: 14 tests, 0 failures. USB hub + RTL-SDR enumerate at high
  speed; GPS MAX-M10S answers UBX (SPG 5.10); SD 4 MiB verify OK; display and touch confirmed by eye.

## [0.13.0] - 2026-10-12

### Added
- `[gps]` GPS comms test over UBX (both test apps): auto-baud, UBX-MON-VER (firmware/hardware/module),
  UBX-MON-RF (antenna status/power, noise, jamming) and UBX-NAV-PVT (fix, satellites, UTC). Tells "no
  data at all" apart from "data but no UBX reply". The NMEA + PPS test is now `[gps_pps]`.

### Fixed
- microSD: the SD driver claimed GPIO45 (slot-0 D4 default), which is the card power enable. D4-D7
  are now set unused for 4-bit mode, and the power GPIO is configured once.
- `[sdcard_format]` formatted the card twice (mount-with-format plus an explicit format). Now formats once.
- Documented the expected "host controller with slot registered" log (esp_hosted holds SDMMC slot 1).

## [0.12.0] - 2026-10-12

### Fixed
- **Chip revision:** the reference unit is ESP32-P4 **rev v1.3**, but the builds required rev ≥ v3.0
  (copied from Waveshare's examples), so the bootloader was rejected. The reference test app now
  selects rev < 3 (`ESP32P4_SELECTS_REV_LESS_V3`, min v1.0) with a `sdkconfig.rev3` overlay for
  newer boards. ADSB_Test keeps rev ≥ 3 for new parts, with a `sdkconfig.rev1` overlay to run on the
  reference unit.
- Reference test app console back on UART0 / CH343 (COM4, reliable auto-reset); USB-Serial/JTAG
  (COM3) mirrors the output.

### Added
- `tools/unity_run.py`: runs Unity tests over a serial port unattended (reset, menu, selectors,
  summary, optional log). Used for the first remote hardware run.
- First hardware results on the reference board (bring-up log): `[bsp]`, `[i2c]`, `[wifi]` and
  `[display]` (init) PASS; microSD detected but exFAT mount fails; USB-A saw no devices; GPS not wired.

### Notes
- esptool matches port names case-sensitively on Windows: `com3` fails on the USB-Serial/JTAG port,
  `COM3` works.

## [0.11.0] - 2026-10-10

### Added
- Reference board tests `[usb]` (USB host on the USB-A port via `espressif/usb` ^1.6.0: lists devices
  incl. behind a hub, flags RTL-SDR 0bda:2838/2832) and `[gps]` (UART2 on P3 header GPIO2/3, PPS on
  GPIO4: baud auto-detect, NMEA count, PPS interval/jitter). `[gps]` also in the ADSB_Test app.
- `bsp_sdcard_format()` / `p4c_sdcard_format()` and an opt-in `[sdcard_format][ignore]` test (ERASES the
  card) for large exFAT cards: ESP-IDF 6.1 FatFs has no exFAT (`FF_FS_EXFAT 0`).
- Reference board README: COM3 = P4 USB-Serial/JTAG, GPS wiring table for header P3, >32 GB SD notes.

### Changed
- Reference test app console moved to the P4 USB-Serial/JTAG (the port the board is connected on);
  USB host hub support enabled; FAT long file names enabled; SD allocation unit 32 KB.

## [0.10.0] - 2026-10-10

### Added
- **Reference document library**: `docs/datasheets.json` lists 63 documents (datasheets, TRMs, design
  guidelines, vendor files, repos) for every part on both boards. `tools/fetch_datasheets.py` (stdlib
  only, curl fallback) downloads them into `datasheets/` (git-ignored, public repo) with SHA-256
  manifest and regenerates the committed index `docs/datasheets.md`. 39 of 41 files fetched (plus 22 links); STUSB4500 and
  CP2102N need a manual browser download (sites block scripts).
- ADSB_Test: ESP32-C5 pin and strap table from the C5 datasheet; P4 strapping pins confirmed from
  the P4 datasheet (GPIO34–38).

### Changed
- ADSB_Test **C5 USB-Serial/JTAG removed from the Dev hub**: on the ESP32-C5, SDIO D3/D2 (GPIO13/14)
  are the same pins as USB D-/D+, so with 4-bit SDIO the C5 is flashed/debugged over UART0
  (FT2232H ch B, auto-reset on CHIP_PU + GPIO28). Dev hub port 2 is spare. GPIO26 gets a 10 kΩ
  pull-up so the C5 can't strap into SDIO download mode.
- ADSB_Test charger proposal **BQ25792 → BQ25798**: TI's BQ25792 pages return 404; the BQ25798
  (same family, adds MPPT) is live, I2C address 0x6B confirmed. Pin compatibility to confirm (Q21).
- P4: GPIO2–5 confirmed free for GPS/PM as long as `EFUSE_JTAG_SEL_ENABLE` is never burned.

### Fixed
- Reference board README: PowerShell paths in the test instructions had tab characters where the
  backslash-t of `\tools` / `\test` should be.

## [0.9.0] - 2026-10-10

### Added
- `common/components/p4_board_common`: shared ESP32-P4 helpers: I2C bus + probe, LEDC backlight
  (supports inverted drive), EK79007 MIPI-DSI panel (DSI PHY LDO), GT911 touch (auto-detects
  0x5D/0x14), microSD on SDMMC slot 0 (power-enable GPIO + I/O LDO). Uses `esp_lcd_ek79007` ^2.0.2
  and `esp_lcd_touch_gt911` ^1.2.1.
- BSP API for both boards (`bsp_i2c_init`, `bsp_display_new`, `bsp_display_backlight_set`,
  `bsp_touch_new`, `bsp_sdcard_mount/unmount`), driven from `board_pins.h`.
- Hardware tests: `[i2c]` scan, `[display]` colour bars + backlight sweep, `[touch]`, `[sdcard]`
  write/read. Reference board also has `[wifi]`: AP scan through the C6 via esp_hosted 3.x and
  IDF 6.1's built-in Wi-Fi remote (`docs/wifi.md`).
- `sdkconfig.defaults` from the Waveshare examples (P4 rev ≥ v3, 32 MB QIO flash, PSRAM 200 MHz,
  bootloader log WARN) plus pinned esp_hosted SDIO pins.

### Notes
- Waveshare's pinned Wi-Fi stack (esp_wifi_remote 1.2.5 + esp_hosted 1.4) doesn't build on
  ESP-IDF 6.1. esp_hosted 3.x host is back-compatible with 1.x/2.x co-processor firmware.
- Both test apps build with no warnings. **Not yet run on hardware.**

## [0.8.0] - 2026-10-10

### Added

  PHY_RST 51, RMII 28–30/34/35/49/50). New signals sit on the reference board's P1/P3 header pins
  where possible, so Phase-1 eval wiring uses the same GPIOs.
- ADSB_Test requirement DISP-04: the panel is a bare COG panel, so its supplies (AVDD 9.6 V,
  VGH/VGL, VCOM, 1V8, LED backlight boost) are copied from the reference board. FPC/touch connector
  pin-outs recorded in the Display sheet.

### Changed
- ADSB_Test LCD and touch resets stay on P4 GPIO33/23 (as reference), not the expander. PHY reset on
  GPIO51 (IDF default). Touch INT newly wired (GPIO26).

### Fixed
- Display sheet design notes didn't render (raw newlines in the KiCad string); now escaped.

- ADSB_Test **7" panel data and stack-up** from Waveshare's dimension drawing and STEP model (no

- Q18 and Q19 answered.

## [0.6.0] - 2026-10-10

### Added
- ADSB_Test **mechanical and RF layout** rules (architecture.md) and new requirements MECH-01..03,
  RF-01..03: screen-sized board with the 7" panel mounted on it; digital connectors on one edge,
  GNSS + m1421 SMA connectors on the opposite edge; optional two-piece RF cans over the m1421

- Open questions Q2a, Q8, Q10, Q15, Q16, Q17 answered.

## [0.5.0] - 2026-10-09

### Changed
- ADSB_Test m1421 integration reworked from the PantsForBirds/adsbee repo docs and firmware:
  - **SYNC is a host-driven input**: high at reset = CC1314 ROM UART bootloader, high at run
    time = sleep + LR2021 hand-off. Driven as P4 OR Dev, with a pull-down. Not a message output.
    The activity outputs SD26 (1090) / SD27 (UAT) go to LEDs and LA CH7 / CH11.
  - Dev-port path is now the ADSBee 1421 Programmer firmware on the RP2040 (power-up auto-reflash
    disabled), so the ADSBee web console AT terminal and firmware uploader work unchanged.
    JTAG stays on the 10-pin header for a Segger J-Link. JTAG over Dev USB isn't provided.
  - New requirement M14-05: the P4 can update the m1421 firmware in the field via the ROM bootloader.
  - Layout rules from the module docs (filled/capped vias, keep-outs, paste on all pads).
- ADSB_Test KiCad library replaced with the official **PantsForBirds/kicad-libs (MIT)** m1421 and
  SCN-2-11 parts (3D models included). SYNC pin type corrected to input. Licence file added.
- LA header CH11 changed from P4->GPS TX to m1421 SD27 (UAT activity).

## [0.4.1] - 2026-10-09

### Changed
- ADSB_Test: C5 module fixed as **ESP32-C5-WROOM-1-N16R8** (16 MB flash / 8 MB PSRAM). Room for
  C5 OTA slots, same module as the C5 DevKit.
- ADSB_Test: LA header changed to a **2×20 keyed box header** matching the Kingst LA5016 40-way
  cable (key-side row: CH0–7, GND, CH8–15, GND, PWM1, PWM2). The second row is reserved for an LA5032.
  LA PWM1 can simulate GPS PPS via a DNP link.

## [0.4.0] - 2026-10-09

### Changed
- ADSB_Test: co-processor changed from ESP32-C6 to **ESP32-C5** (dual-band Wi-Fi remote,
  same SDIO/esp_hosted host side).
- ADSB_Test: "M1421" identified as the **ADSBee m1421** dual-band ADS-B module. Pad-level
  integration plan (UART + SYNC + RESET to the P4, SWD + UART to the Dev port via an RP2040
  debugprobe, RF combiner copied from the ADSBee 1421 carrier).
- ADSB_Test: USB-A now targets 1 SDR (AIS etc.), 2 supported, 4 nice-to-have via an external
  hub. eFuse limit 1.5 A, 5 V buck 3 A. Dev bridge FT4232H changed to FT2232H.
- ADSB_Test: battery 2S1P 18650 sized from a new power budget (≥ 1 h with everything running).
- ADSB_Test: slow control lines moved to a TCA6408A I2C GPIO expander (P4 GPIO use ≈ 44/55).
- ADSB_Test: audio confirmed dropped, microSD confirmed kept.

### Added
- ADSB_Test KiCad project library: ADSBee m1421 symbol + footprint and MiniCircuits SCN-2-11
  symbol + footprint, from the ADSBee 1421 carrier design (GPL-3.0, attribution in `lib/README.md`).
- ADSB_Test "Test Debug" sheet: 2×10 header for the Kingst LA5016 (16 signals) and test points
  on every rail. Board pin map updated to match.
- Reference board: key parts recorded from the Waveshare schematic.

### Changed (repository)
- `hardware/vendor/` folders are git-ignored (the repo is public).
